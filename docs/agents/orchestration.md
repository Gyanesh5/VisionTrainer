# 实施编排纪律（orchestration）

> 适用范围：所有多子代理实施流程（implement-spec 的 implementer/merger、批量修复、票面工作）。用户 2026-11-18 定稿，原文收录；目标是减少重复上下文与无效工具往返，同时保持实现质量。

- **控制命令时长**：长命令的 `timeout` 设置为至少 `540s`，避免因工具超时造成空转和重复执行。
- **压缩测试输出**：测试命令将完整输出重定向到文件，只提取摘要行返回上下文，例如 `passed`、`failed`、`error` 和退出状态；禁止把大段测试日志直接带回。
- **批量操作**：优先批量读取、批量修改、批量运行测试，并聚合结果，避免一项操作一次往返。
- **控制任务粒度**：单票预计超过 `1000` 行 diff 或 `150` 轮交互时，拆成多个独立任务。跨多个模块的工作按机制、接线、验证阶段拆分。
- **减少重复预读**：编排者先读取共享笔记、ADR（Architecture Decision Record，架构决策记录）、issue 和术语表，为每个子代理提供与其任务相关的短摘要；子代理仍需自行检查实现所需的源码。
- **限制上下文污染**：子代理只返回结论、变更文件、关键证据和测试摘要，不返回完整日志、完整文件内容或无关探索过程。
- **安排代理职责**：设计和核心实现使用强模型；机械修复、合并和测试任务优先使用轻模型。若平台不支持模型分层，则保持职责分离。
- **恢复时避免重建**：上下文中断后，使用结构化摘要恢复：当前目标、已完成事项、未完成事项、变更文件、测试状态和下一步；不要重新发送全部历史。
- **验证标准**：只有实际测试通过才能报告完成；跳过的测试必须明确说明，失败时只报告摘要和失败位置。

**核心执行原则**：先拆分，再批量；测试只回传摘要；长命令使用充足超时；每个子代理只接收完成当前任务所需的上下文。
