# 0019 - classify 错误分析按图对账，GT 冻结「图 → 类」映射

Status: accepted（2026-11-23，用户裁决；源自 #157）

错误分析此前只有逐框口径（IoU 匹配逐框记 TP/FP/FN，GT 读 Run 启动时冻结的 val 标签副本）；classify 没有框、推理结果只有各类概率，所以 classify Run 点「运行错误分析」恒报 409「缺 val 标签冻结副本」，重训也无效。classify 改按图对账，并与逐框同构：一图至多一条记录写入 `run_sample_errors`，`kind` 沿用 tp/fp/fn/confusion 四态，GT 读 Run 启动时冻结的「图 → 类」映射 `labels_frozen/val/classes.json`。缺映射的旧 Run 首次分析时，从逐 Run 入口的 val 链接树（`<run_dir>/data/val/<类别名>/`，启动时落盘、此后不改写）补写——这是「缺冻结副本直接 409、不设回退分支」的唯一例外。

## Considered Options

- **如实拒析（classify 不支持错误分析）**：改动最小，提示也不再误导；但 classify 的闭环缺了「错误分析 → 改类 → 复训」一段，拒绝。该文案保留为「缺冻结副本且补写不出」时的 409 提示。
- **为 classify 另建一套分析表与页面**：口径可以更贴近分类；但混淆矩阵、阈值扫描、点格下钻都要再写一遍，LLM 复盘读的 summary 结构也要分叉。逐图记录与逐框记录同构后这些全部零改动复用，拒绝。
- **汇总行改出准确率**：分类任务最自然的指标；但 summary 结构供界面与 LLM 复盘共用，classify 下 R 就是有真值图在该口径下的准确率，不为它分叉结构，拒绝。
- **冻结形态用逐图 txt（内容写类名）**：与逐框「一图一 txt」的目录形态一致；但分类的标签本来就是「一图一类」，一份 JSON 读写各一次、一眼可读。选 JSON，采纳。
- **不另存副本，直接读链接树**：链接树本就是启动时产物；但它同时是训练入口，把对账真值挂在一个另有用途的目录上，入口形态一变对账口径就跟着变。冻结副本独立落盘，链接树只作旧 Run 的补写来源，拒绝。
- **旧 Run 一律重训，不开补写路径**：与「不设回退分支」字面一致；但该规则防的是随改标漂移的旧派生目录，链接树是 Run 自己落盘即归档的启动时产物，与启动冻结同源同时点。让用户为一个平台缺口重跑训练，拒绝；补写路径仅对 classify 开放。
- **补写时兼容 `{NN}_` 前缀目录**：能让 ADR 0017 之前的 Run 也补上；但 ADR 0017 已裁决不做向后兼容，前缀时代的 Run 重训，拒绝。

## Consequences

- classify 与逐框任务共用 `run_sample_errors` 与整条分析链路。classify 记录的 `box` 为空、`iou` 为 null，读这些字段的消费方须容忍空值（现有消费方已容忍）。
- 运行快照新增 `task_type`，错误分析据此选口径；早于该字段的 Run 回读任务所属数据集的元数据。
- 「缺冻结副本 409、不设回退分支」多了一个限定例外：仅 classify、仅读 Run 自己归档的 val 链接树、仅认类别真名目录。其它任务与其它来源不得援引。
- 叠加图对 classify 退化为左上角文字标注。注记只用 ASCII：Pillow 内置字体没有中文字形，类名为中文时同样渲染成占位方框（既有局限）。
- 未决：Run 有分析结果后，部署与发布取阈值扫描的建议 conf；classify 没有 FP（误检）时该建议恒为下限 0.05。是否让 classify 部署沿用 `train_args.conf`，待裁决（#157）。
