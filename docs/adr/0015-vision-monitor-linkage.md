# 0015 - 与 vision-monitor 联动：主动学习环的训练平台侧配套

Status: accepted（2026-11-18，grill 定案；vision-monitor 侧对应其仓 ADR 0014/0015）

## Context

vision-monitor（产线推理平台，每工位一台 Jetson）已在其仓定案再训练闭环：轻量标注留在监控侧（操作员复核预标注初稿）、样本经导出包（图片+LabelMe JSON+classes.txt+manifest）出库、模型回接走「监控端拉取 .pt + 配置热装配」、样本状态机预留 exported→ingested→trained 回写位；v1 人工 → v2 拉取自动化 → v3 全自动三阶段爬坡。导出包格式与训练平台托管导入路径 A、审查状态键（checked/vt_review）天然对齐——格式契约已通。

训练平台侧缺口：模型库只有列表/删除，没有文件下载面；样本导入靠人工解包注册；无状态回写。本 ADR 定平台侧配套面。

## Decision

1. **术语与动作分离**：部署（导出 ONNX 组装进标注端模型库）维持原义；新增**模型发布**——把某运行的 best 权重与元数据（类别表、建议置信度、指纹）打包进发布目录，配限时签名 URL 供监控端拉取，发布记录留档、只增不改。签名 URL 复用 thumbs 管线模式。词汇见 GLOSSARY 联动域。
2. **部署页升级为模型页，Run 产物权重为模型真源**：模型页浏览全部 Run 的权重，部署与发布记录挂在 Run 权重上、同页不同动作；模型库目录与发布目录降为派生产物（部署组装物、发布打包物，可清理重建，不再作独立模型账本）。Run 删除遇已发布/已部署权重时的策略随实施票定案。
3. **样本回流为平台内置导入源**「从 vision-monitor 拉取」：填监控端地址与过滤（任务、时间窗、状态）→ 后端调其导出 API → 落盘 → 走既有托管导入链 → 进行中操作三层反馈；不建平台外脚本。
4. **导出包 manifest 落 dataset meta**（工位、模型指纹、时间窗、样本清单），逐条样本不建独立表；样本溯源与多工位分组评估读 meta。
5. **状态回写全链**：exported→ingested 在拉取导入成功时回写；→trained 在消费该数据集的 Run 终态成功后回写。回写由平台侧发起（拉取器与 Run 生命周期各挂一点）。
6. **backlog 处置**：#114（视频抽帧导入）关闭为 superseded——监控侧沿事件+心跳采样已覆盖，平台免 cv2 依赖裁决；#112（受管 PT 预标注）维持 backlog——环内预标注由监控侧源头发起，平台侧只剩外部杂源导入场景；#113（独立评估任务）标注为 v3 前置。
7. **v3 张力挂账**：监控侧 v3「训完自动评估、达标自动上线」与本仓 ADR 0006「全自动无人闭环不做」存在冲突，v3 启动前开专门裁决，本 ADR 不预支结论。

## Consequences

- 契约方向固定：训练平台开「可拉取」面（导出包由平台发起拉取、模型文件被监控端拉取），监控端无入站写面（其 ADR 0014 边界）。
- dev 机同机共卡（models.yaml 绝对路径引用 runs 权重）为过渡形态；生产拓扑按其 ADR 0014（工位 Jetson + 训练专机同产线局域网）。
- REST 面新增（发布、拉取导入、状态回写、模型文件签名 URL）随实现票同步 docs/api.md；模型页重整同步 DESIGN.md。
- 模型真源化后，Run 删除（训练记录单条可删的既有能力）与「已发布/已部署权重的存续」出现新的交互——发布/部署的物理拷贝留在派生目录，账目随 Run 消失；冲突策略（阻止/警告放行）须在实施票中显式裁决，不得默默假设。
- 两平台保持可独立部署：平台对监控端的感知限于「可寻址的导出 API + 样本状态 API」，监控端对平台的感知限于「可拉取的发布 URL」。
