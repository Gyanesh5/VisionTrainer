# 0018 - 发布面血缘声明：双字段落位与契约 v1.1

Status: accepted（2026-11-23，随契约 v1.1 修订与架构评审 T1/T2 定案记账）

## Context

2026-11-23 两仓各做一轮联动域架构评审。推理端侧评审的 Strong 候选 F1（该仓票 #190）：发布拉取幂等键全局唯一、族基线却由「从哪个族页面发起」决定——错误族页面拉取会静默挂错族；定案硬校验「源基线指纹 ∈ 族指纹集合」，缺字段即拒绝，**修复前置字段由本仓发布面提供**。

同日本仓侧评审确认：运行快照 weight 段（snapshot.py）早已冻结起训权重身份（本地文件记完整 sha256、官方模型名记 resolved_by_trainer），发布组装 metadata 时却不读——血缘数据链已通九成，缺的只是发布面这一跳。另发现契约 §5.4 字段名 `rid` 与实现 `release_id` 漂移、清单 URL 签发死绑首发时刻等问题（随 v1.1 一并修订，偏差登记 §10.10-12）。

grilling（2026-11-23）定案血缘声明口径。

## Decision

1. **双字段**：发布面携带两类血缘——`baseline_sha8`（权重血缘：该 Run 起训权重的内容指纹，快照 weight 段冻结口径）+ `sample_models`（数据血缘：该 Run 实效集命中的各导出批次 manifest.models 并集）。
2. **null 语义三分支**：本地文件起训 → 指纹；官方预训练权重或无快照 Run → null（**null 是合法值**=无血缘声明，推理端作开新族候选、走人工确认门）；字段缺失（旧版平台发布）→ 推理端拒绝。null ≠ 缺失——从官方预训练起训是合法常态，不得被硬校验拦截。
3. **无快照旧 Run 取 null**：宁可空不可错——Task.base_model 本地路径现算可得更早 Run 的指纹，但文件若已变更则血缘失真，快照的意义就是冻结。
4. **sample_models 实效集口径、同形同名列**：取数与契约 §6.2 trained 归因同构（manifest 样本清单 ∩ 实效集），字段形态与导出包 manifest.models 一致（`[{model_id, model_sha8}]` 去重保序），对端对账零翻译。
5. **实现分工（T2 产查询、T1 消费）**：数据血缘取数与 trained 归因是同一个 join（producer_writeback.trained_attribution；实施时先命名 trained_sample_ids，保留为兼容投影后经 review 判死代码删除，定名 trained_attribution）——切片链归因修复票（评审候选 T2）顺带把归因查询重构为共享函数（返回 sample_ids + 命中批次 models 并集），发布面票（候选 T1）消费；baseline_sha8 部分只读快照、不受阻塞可先行。
6. **契约先行**：契约 v1.1 修订（§5.4 增字段+勘误+现签语义、§9/§10 同步）先于实现票落定，推理端 #190 凭定稿字段解除阻塞。

## Consequences

- 联动契约升 v1.1：baseline_sha8/sample_models 为新增可选字段（§9 兼容承诺，不 bump 主版本）；`rid`→release_id 为勘误；download_url 现签语义为澄清（约束账目行不约束响应视图）。
- 五张实施票：切片归因（T2）、发布面血缘字段（T1，sample_models 部分依赖 T2）、下载面现签+密钥独立（T3）、trained 回写重放（T4）、拉取导入 fail loud+卫生（T5+T6）；本仓 §10 偏差 10-12 随实施逐条勾销。
- GLOSSARY 联动域新增「源基线指纹」「样本溯源模型清单」词条。
- 推理端侧义务随其 #190 落地（三分支校验规则），其 ADR 归其仓——本 ADR 只定训练平台侧供给语义。
- 权重血缘为 null 的发布（官方预训练起训）在推理端是「开新族候选」：族谱连续性取决于训练侧是否从上一代权重起训，属使用纪律，契约只负责如实声明。
