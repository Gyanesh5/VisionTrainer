# 0013 - Run 目录两级可读命名

Status: accepted（2026-11-12，源自「不开软件找不到训练记录目录」用户反馈）

产物根 `runs/` 下两级目录全部可读：任务级取任务名（清洗文件系统非法字符、截 80 字符），Run 级取 `{开训时刻 %Y%m%d_%H%M%S}_r{轮次}`（与 `runs.started_at` 同源）。uid（8 位 hex）保留为库内主键与对外 API/WS 标识，不再承担文件系统可读性；任务重名或 Run 同级重名时兜底追加 `-{uid}` 后缀保证唯一。存量随机名目录在落地时一次性迁移（目录改名 + `runs` 表 `run_dir/best_pt/last_pt` 同步改写），平台代码不含迁移与兼容层。

## Considered Options

- **维持 uid 两级**：路径与库零同步成本，但不打开平台无法定位任何一轮训练，拒绝。
- **拉平单层**：少一跳，但文件系统丢任务分组，与训练记录单表按任务分组的口径不一致，拒绝（用户裁决保两级）。
- **任务目录再加时间戳前缀**：现有任务名约定已含创建时刻（`数据集_模型_时间`），双重盖章冗余，拒绝。

## Consequences

- 任务无改名入口，任务目录名一经落盘永不漂移；未来若引入改名，属目录漂移问题，须同步迁移。
- `runs` 表三路径列与磁盘目录名同名实为一体：任何绕过出队命名函数建目录的新代码都会造成库盘漂移。
- 归档 `payload.json` 内嵌的绝对路径属历史输入记录，不回写；`trainer_entry` 以 `run_dir` 父/子名喂 Ultralytics `project/name`，对名字内容零假设。
